# Руководство по аудиту и усилению безопасности

**Цель документа:** Предоставить информацию о текущей архитектуре проекта для проведения оценки уязвимостей и настройки мер защиты перед развертыванием на производственных серверах ЮФУ.

## 1. Архитектура и компоненты

Проект состоит из двух изолированных сервисов, взаимодействующих через HTTP/REST API:

1.  **Frontend (Next.js)**
    *   **Расположение:** папка `/React NextJS museum`
    *   **Технологии:** React 18+, TypeScript, Tailwind CSS, HeroUI.
    *   **Роль:** Клиентское приложение. Рендеринг страниц происходит на стороне сервера (SSR) или статически (SSG). Взаимодействие с пользователем.
    *   **Критические точки:** Формы ввода данных, маршрутизация, обработка cookies/session.

2.  **Backend / CMS (Strapi v4/v5)**
    *   **Расположение:** папка `/museum-cms`
    *   **Технологии:** Node.js, Koa.js, SQLite (dev) / PostgreSQL (prod recommended).
    *   **Роль:** Хранение контента (новости, страницы), управление доступом, логика бронирования (временно деактивирована в UI, но код активен).
    *   **Критические точки:** Панель администратора (`/admin`), публичные эндпоинты API (`/api/*`), загрузка медиафайлов.

## 2. Текущее состояние безопасности (Known Issues & Risks)

Ниже перечислены известные ограничения и потенциальные векторы атак, которые требуют внимания при настройке продакшена.

### 2.1. Управление доступом (RBAC) в Strapi
*   **Статус:** По умолчанию роль `Public` имеет минимальные права. Однако для работы сайта необходимо вручную выдать права `find` (чтение) для коллекций контента.
*   **Риск:** Ошибочное предоставление прав `update`, `delete` или избыточных прав `create` роли `Public` позволит любому посетителю изменять контент или спамить базой данных.
*   **Рекомендация:** Строго следовать инструкции в `DEPLOYMENT.md`: выдавать только `find` для новостей/страниц. Для формы бронирования (если она будет включена) — только `create`. Никаких других действий.

### 2.2. Защита персональных данных (PDP)
*   **Контекст:** Модуль бронирования (`Bookings`) собирает ФИО, телефон и email. Согласно ФЗ-152, эти данные чувствительны.
*   **Текущая реализация:**
    *   Данные передаются по HTTPS (зависит от настройки Nginx).
    *   В коде frontend запрос к API фильтрует поля: `?fields=date&filters[processed][$eq]=true`. Это гарантирует, что личные данные других пользователей не утекают в календарь занятости.
*   **Риск:** При прямом обращении к API без фильтрации полей (если злоумышленник узнает структуру) возможна попытка чтения всех полей записи, если права `findOne` будут ошибочно открыты.
*   **Рекомендация:** Убедиться, что у роли `Public` **ЗАПРЕЩЕНО** действие `findOne` для коллекции `Bookings`. Только `find` с жесткой фильтрацией на уровне кода или middleware.

### 2.3. Секреты и конфигурация (.env)
*   **Статус:** Файлы `.env` исключены из Git. Примеры лежат в `.env.example`.
*   **Риск:** Использование дефолтных значений ключей шифрования (`APP_KEYS`, `JWT_SECRET`).
*   **Рекомендация:** Перед запуском генерировать уникальные криптостойкие строки для всех секретов. Не использовать значения из примеров.

### 2.4. Зависимости и Supply Chain
*   **Статус:** Используется стандартный набор npm-пакетов.
*   **Риск:** Наличие устаревших пакетов с известными CVE.
*   **Действие:** Запустить аудит зависимостей перед деплоем:
    ```bash
    # В папке frontend
    npm audit fix --force
    
    # В папке backend
    cd ../museum-cms
    npm audit fix --force
    ```
    *Проверить вывод на наличие критических уязвимостей высокого уровня.*

### 2.5. Медиа-файлы (Uploads)
*   **Статус:** Strapi позволяет загружать изображения.
*   **Риск:** Загрузка вредоносных скриптов (XSS через SVG, исполняемые файлы), переполнение дискового пространства.
*   **Рекомендация:**
    1. Настроить лимит размера файла в настройках Upload plugin в Strapi.
    2. Разрешить загрузку только типов MIME: `image/jpeg`, `image/png`, `image/webp`. Блокировать `image/svg+xml` (потенциальный XSS) и любые другие форматы.
    3. Папку `uploads` хранить вне корня веб-сервера или настроить строгие права доступа (read-only для nginx).

## 3. Чек-лист для инженера безопасности

При подготовке продакшен-среды прошу выполнить следующие пункты:

1.  [ ] **SSL/TLS:** Настроить сертификат Let's Encrypt или ведомственный SSL для доменов `museum.sfedu.ru` и API. Принудительный редирект HTTP -> HTTPS.
2.  [ ] **CORS:** Настроить CORS в Strapi (`config/middlewares.js`) так, чтобы разрешать запросы только с домена фронтенда. Отключить wildcard `*`.
3.  [ ] **Rate Limiting:** Настроить ограничение частоты запросов (rate limiting) на уровне Nginx или middleware Strapi для предотвращения DDoS и брутфорса панели `/admin`.
4.  [ ] **Брандмауэр (Firewall):** Открыть порты 80/443 для внешнего мира. Порты 3000 (Next.js) и 1337 (Strapi) должны быть доступны **только локально** (localhost) или через защищенный туннель. Прямой доступ снаружи запрещен.
5.  [ ] **Аутентификация Админа:** Включить 2FA (Two-Factor Authentication) для всех аккаунтов администраторов в Strapi.
6.  [ ] **Логирование:** Настроить централизованный сбор логов ошибок приложения и обращений к API. Логи не должны содержать полных номеров телефонов или паролей (маскирование sensitive data).
7.  [ ] **Backup:** Настроить регулярное резервное копирование базы данных (PostgreSQL dump) и папки `uploads`.
